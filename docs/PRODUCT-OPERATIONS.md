# Product Operations Readiness

This release separates product completeness from the later security-hardening phase.

## Implemented product controls

- organization-scoped data model
- plan entitlements and usage metering
- Stripe subscription state synchronization
- GitHub App installation lifecycle and repository-scoped access tokens
- durable webhook idempotency and retries
- deterministic verification decisions
- AI explanation queue with bounded retries
- audit log for organization/project/member/billing/verification administrative actions
- CI validation and container publication
- GitOps image pinning and Argo CD declarations

## External production dependencies

A deployable product still requires customer-owned resources that cannot be generated by a source archive:

- a public HTTPS domain for webhooks
- a registered GitHub App and installation
- OpenAI API credentials and chosen model access
- Stripe account/products/prices/webhook secret
- a GitHub repository and GHCR package permissions
- managed PostgreSQL
- a Kubernetes cluster and Argo CD
- an identity provider/gateway

These are environment dependencies rather than missing source-code modules.

## Security boundary

The full production security phase is intentionally excluded as requested. Before untrusted third-party workloads or public SaaS access, add authentication/SSO, authorization enforcement at the trusted edge, tenant isolation controls, stronger runner isolation, network policies, secret-management hardening, abuse controls, and incident-response tooling.

## Local Kubernetes rollout troubleshooting

If `scripts/start-local.ps1` cannot complete a backend or frontend rollout, the script now prints Deployment/ReplicaSet/Pod state, current and previous container logs, and namespace events before exiting. You can collect the same read-only snapshot independently with:

```powershell
.\scripts\diagnose-local.ps1
```

For a backend timeout, inspect the first backend traceback and the affected pod's `Terminating` state before deleting anything. The bootstrap deliberately never deletes the PostgreSQL StatefulSet or PVC. Startup has a dedicated probe to avoid liveness restarts during schema initialization; background workers also receive a bounded shutdown window.
